## Story 12-2-temporary-lob-lifecycle
- [Phase 3 — create-story] 12.1's slot-holding-handle model is structurally incompatible with binding a created temp LOB; 12.2 must narrow it for created-temp handles — an epic-level design tension the architecture's "one lifecycle model for all server-backed handles" note did not anticipate.
- [Phase 3 — create-story] node-oracledb thin/lob.js init() temp-detection has a JS operator-precedence bug (a & B === B); taking the reference literally would mark every fetched BLOB temporary. Port only the TEMP bit and measure live.
- [Phase 5 — dev-story] Story ACs missed a flag-threading site: OracleBind._validate rejects the value type at CONSTRUCTION, upstream of _prepareStatement. Any future story adding a new bind-value type must audit that validator too, not just the connection-layer unwrap.
- [Phase 5 — dev-story] The "measure, don't assume" mandate paid off twice: it closed the 12.2-targeted ledger item as a non-issue AND surfaced an unrelated pre-existing IN OUT OUT-locator leak plus ORA-22922 handle-consumption — none of which were in the story's hypotheses.
- [Phase 5 — dev-story] Measured on both fixtures: NO fetched shape (TO_CLOB, PL/SQL CLOB OUT, table CLOB/BLOB, FOR UPDATE) sets the locator TEMP bit or allocates session temp-LOB space — so AC3's narrowing fallback was never needed and free-on-close stays generic.
- [Phase 7 — code review] AC4 and AC5 of this story contradicted each other (AC5 promised a fetched handle is bindable; AC4 mandated fetched handles keep holding the in-flight slot, making that unreachable). Resolve cross-AC conflicts at story-authoring time, not in Completion Notes.
- [Phase 7 — code review] The "non-ASCII test fixtures use explicit Dart escapes" rule has now been stated and not followed in two consecutive stories (12.1, 12.2). Its root cause is the 12.1 convention file itself, which still holds raw literals — enforce by lint, normalize that file, or drop the rule from the AC template.
- [Phase 7 — code review] Do NOT port node-oracledb's TNS_LOB_LOC_FLAGS_ABSTRACT clause in a future parity pass: its JS operator-precedence bug marks every fetched BLOB temporary and would queue innocent locators for FREE_TEMP.
- [Phase 7 — code review] In thin (Tier-A) mode the security lens routed two items to a code-quality reviewer that Tier A does not run; such handoffs land nowhere unless triage picks them up.

- [Phase 3 — create-story] 12.3's scope had to be SPLIT: the ledger targets the whole lazy-handle wrap at 12.3, but the nested-CURSOR()/REF-cursor-OUT half sits behind a pre-existing decode limitation that makes it unprovable under the dual-env mandate. - [Phase 3 — create-story] Two 12.3-targeted ledger items are resolvable only BECAUSE this story owns the driver-side chunk boundary (surrogate join on streamed write; stale-_length immunity via stop-on-empty-READ) — evidence that "revisit when X lands" targets do pay off.
- [Phase 5 — dev-story] 21c POISONS THE TRANSPORT on a cursor row carrying a LOB (23ai recovers) — one such query costs the caller their connection. Needs an epic-level decision on priority; blocks wrapping nested-CURSOR()/REF-CURSOR LOB columns.
- [Phase 5 — dev-story] AC8's measure-don't-assume paid off a third time: turned the reject-path cursor leak from masked/unprovable into a live-measured defect with a real fix, and revealed that EVERY CLOB on an AL32UTF8 database arrives UTF-16BE — simplifying the boundary design and exposing a coverage hole (the UTF-8-form branch is unreachable on both fixtures).
- [Phase 5 — dev-story] Full-length single READ scales super-linearly (33.5M-unit CLOB = 141s on 23ai; doubling size ~ quadruples time) — points at the LOB_DATA accumulate/concat path. The new streams are the linear alternative.
- [Phase 5 — dev-story] Story-authoring quality was high here: the only cross-AC tension (throw-on-zero-progress vs an explicit amount may overshoot) was resolvable in-code by capping the seam's amount at the units that can exist — no deferral needed. Contrast with 12.2's AC4/AC5 contradiction.
- [Phase 7 — code review] AC2 shipped with an internal contradiction: "pieces of at most pieceSize units" vs its own "hold trailing units back and join them with the next piece". AC-authoring note: a hold-back-and-join clause ALWAYS breaks a hard per-piece size cap. Dev resolved it correctly in code but propagated the false bound into public dartdoc + README, and the supplemental-plane integration case dropped its <= pieceSize assertion instead of flagging the conflict.
- [Phase 7 — code review] The synchronous-validation fix required editing two PRE-EXISTING unit assertions from expectLater(future, ...) to expect(() => ..., ...) — the tests themselves had encoded the defect (async delivery of an ArgumentError). Watch for tests that pin the wrong shape.
