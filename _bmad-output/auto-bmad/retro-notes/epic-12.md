## Story 12-2-temporary-lob-lifecycle
- [Phase 3 — create-story] 12.1's slot-holding-handle model is structurally incompatible with binding a created temp LOB; 12.2 must narrow it for created-temp handles — an epic-level design tension the architecture's "one lifecycle model for all server-backed handles" note did not anticipate.
- [Phase 3 — create-story] node-oracledb thin/lob.js init() temp-detection has a JS operator-precedence bug (a & B === B); taking the reference literally would mark every fetched BLOB temporary. Port only the TEMP bit and measure live.
- [Phase 5 — dev-story] Story ACs missed a flag-threading site: OracleBind._validate rejects the value type at CONSTRUCTION, upstream of _prepareStatement. Any future story adding a new bind-value type must audit that validator too, not just the connection-layer unwrap.
- [Phase 5 — dev-story] The "measure, don't assume" mandate paid off twice: it closed the 12.2-targeted ledger item as a non-issue AND surfaced an unrelated pre-existing IN OUT OUT-locator leak plus ORA-22922 handle-consumption — none of which were in the story's hypotheses.
- [Phase 5 — dev-story] Measured on both fixtures: NO fetched shape (TO_CLOB, PL/SQL CLOB OUT, table CLOB/BLOB, FOR UPDATE) sets the locator TEMP bit or allocates session temp-LOB space — so AC3's narrowing fallback was never needed and free-on-close stays generic.
- [Phase 7 — code review] AC4 and AC5 of this story contradicted each other (AC5 promised a fetched handle is bindable; AC4 mandated fetched handles keep holding the in-flight slot, making that unreachable). Resolve cross-AC conflicts at story-authoring time, not in Completion Notes.
- [Phase 7 — code review] The "non-ASCII test fixtures use explicit Dart escapes" rule has now been stated and not followed in two consecutive stories (12.1, 12.2). Its root cause is the 12.1 convention file itself, which still holds raw literals — enforce by lint, normalize that file, or drop the rule from the AC template.
- [Phase 7 — code review] Do NOT port node-oracledb's TNS_LOB_LOC_FLAGS_ABSTRACT clause in a future parity pass: its JS operator-precedence bug marks every fetched BLOB temporary and would queue innocent locators for FREE_TEMP.
- [Phase 7 — code review] In thin (Tier-A) mode the security lens routed two items to a code-quality reviewer that Tier A does not run; such handoffs land nowhere unless triage picks them up.
