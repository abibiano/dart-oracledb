## What Went Well

### Architecture Review Discipline — Two Epics Running

The Epic 10 → 11 preparation tasks (arch review of the BATCH_EXECUTE surface, plus the branch-vs-new-class decision) were both done before Story 11.1 ACs were authored. Result: not a single mid-story AC amendment forced by a protocol-shape surprise — a direct contrast to Epic 10's Story 10.4, where the csfrm model wasn't reviewed deeply enough and had to be amended during review. The action item Epic 10 raised ("cover the full protocol surface, not just the headline") was applied and worked.

### Adversarial Review Caught Silent-Data-Integrity Bugs, Every Story

The most valuable class of bug for a database driver is the one that silently returns or stores wrong data. The panel caught one in nearly every story:

- 11.1: invalid-JSON bind value leaking into the error message; non-finite double reaching the wire.
- 11.2: N>1 PL/SQL leaking its NO_IMPL_REL server cursor — an **ORA-01000 "maximum open cursors" risk on pooled connections**, found independently by both the Blind and Edge Case Hunters.
- 11.3: batch-error cache eviction invalidating a **still-valid cached cursor on every batch error** (node-oracledb `processErrorInfo` parity).
- 11.4: `_flushOutBinds()` missing the `dmlRowCounts` decode flag (stream desync / silently-empty result on the RETURNING error path); an omitted required IN slot **silently binding SQL NULL** instead of erroring; a duplicate RETURNING bind name **silently dropping a column's returned values**.
- 11.5: a periodic 26-char CLOB test payload that made a **shift-by-26 corruption invisible to its own equality check**.

Twenty-two patches; none cosmetic.

### Reference-First Discipline Held — Including a Deliberate, Documented Deviation

Every wire-level decision was verified against `reference/node-oracledb`: AC3's `ttcBindArray` deviation confirmed reference-correct (the spec text was the defect, not the code); 11.2's cursor requeue matched `returnStatement`; 11.3's cache-eviction guard matched `processErrorInfo`; 11.4's omitted-OUT-slot behavior matched `writeBindParamsRow`'s `isReturnBind` skip. Where the team chose to diverge — rejecting duplicate RETURNING bind names pre-wire instead of node-oracledb's silent last-wins — it was a conscious, documented safety decision, not drift.

### Test Assertions Were Themselves Hardened (Story 11.5)

11.5 spent its entire patch budget (10, all test-only) tightening the epic's own tests: `hasLength(1)` → cross-checking the actual returned id against its row's generated primary key; loose bounds (`greaterThanOrEqualTo(6)`, `lessThanOrEqualTo(3)`) → `equals()`. Tightening those bounds *surfaced that the true counts were different* (9 committed rows, not 6; 4 cached SQL texts, not 3). Loose assertions had been hiding real behavior. This is the right instinct for a closeout story.

### Dual-Env Rigor Surfaced (and Correctly Isolated) a Real 21c Server Limitation

11.3 found that Oracle 21c under-counts `dmlRowCounts` for a successful row that follows a batch error inside a MERGE (23ai returns `[1,0,0,1]`; 21c returns `[1,0,0,0]` for identical binds — the row is verifiably committed). The decoder was proven faultless (it relays the server's UB8 array exactly). The response was exemplary: dismiss as a documented platform limitation, split the integration test into option-isolated MERGE cases (`dmlRowCounts` alone, `batchErrors` alone), and flag it for future MERGE-touching stories. This is what the dual-env mandate is for.

## Challenges

### CI Coverage Floor — Now Four Consecutive Epics Stale

`ci.yml` still enforces `threshold=68`, set from a 2026-06-10 (Epic 7) measurement. Actual measured line coverage is ≥73.81%, and Epic 11 only *added* tests (86+ net across the epic). The floor is not dangerously low — it's meaningless: a gate five-plus points below reality catches nothing. This was an Epic 8 action item, escalated in Epic 9 and again in Epic 10, and still open. It is the single most persistent process miss in the project.

### Cross-Story Decode-Flag Coupling (11.3 → 11.4)

The `dmlRowCounts` decode flag had to be threaded through several receive paths. 11.3 forwarded it in the LOB-rebuild path as a "latent trap" fix (unreachable then, live in 11.4). 11.4 then found `_flushOutBinds()` *still* omitted it on the RETURNING error path. The `executeMany` option flags (`batchErrors`, `dmlRowCounts`) must be threaded consistently through **every** decode entry point, and the batch stories seeded traps for each other. A single "option-flag threading" checklist across the receive paths would have caught the `_flushOutBinds` gap in 11.3 rather than 11.4.

### `deferred-work` `target:` Field Still Not Enforced

Third epic in a row. Epic 11's new deferrals precisely cite source locations but none carries a `target:` story. Low-severity items (`OracleBatchError` equality, `ttcExecOption*` naming, test-helper duplication) accumulate without a home. The field being "recommended but not enforced" means it is, functionally, not happening.

## Key Insights

1. **The pre-story architecture-review pattern is now proven and repeatable.** Epic 10's thin model and Epic 11's BATCH_EXECUTE mapping both eliminated mid-story protocol-shape surprises. Any epic that adds a protocol shape (Epic 12's server-backed LOB handle is the next one) should get the same treatment. It is the highest-ROI process the project has.
2. **Bulk operations concentrate risk in cursor lifecycle.** Three of Epic 11's production patches (11.2 NO_IMPL_REL leak, 11.3 cache eviction, 11.4 decode-flag desync) were server-cursor/state lifecycle bugs — batch ops keep cursors alive for REEXECUTE, so leaks and stale-cache evictions are the native hazard. **Epic 12's LOB streaming inherits exactly this discipline** (server-backed handles, in-flight/close/leak guards) per `architecture.md` — the 11.x cursor-lifecycle lessons transfer directly.
3. **Adversarial review earns its cost on silent-wrong-behavior bugs.** For a DB driver, a bind that silently stores NULL, a RETURNING that silently drops a column, or a test whose periodic payload hides corruption are worse than crashes. The panel caught this class every story. This is the argument for keeping the 3-layer review on data-path stories.
4. **Loose test assertions hide real behavior — tighten to `equals()`.** 11.5's bound-tightening changed *pass/pass* to *pass-with-the-right-number*, revealing the committed count was 9 not 6. A green test with a loose bound is a weaker signal than it looks. Closeout stories should audit assertion strictness, not just coverage count.
5. **Option flags that thread through multiple decode paths need a threading checklist.** The `dmlRowCounts`/`batchErrors` flags leaked a trap from 11.3 into 11.4 because they must be forwarded at every receive entry point. When a boolean option changes the wire-decode shape, enumerate every decode site in the story that introduces it.
6. **The 68% coverage floor is now a governance problem, not a technical one.** Four epics of raising it and not doing it means the mechanism (a retro action item with an owner) isn't working. It needs to become a one-line CI change bundled into the next story's diff, or it will still be open at Epic 12's retro.
