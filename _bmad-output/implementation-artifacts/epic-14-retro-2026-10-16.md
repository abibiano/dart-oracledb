## Findings

Disposition key: FIX = fix now, DEFER = tracked for later, ACCEPT = recorded deviation.

### Diff-scope review (bmad-review: adversarial, edge-case-hunter, verification-gap)

- **F1 (FIX, medium): a single region-id alias collision makes `timeZoneRegionName` permanently unusable.** `connection.dart:3932-3936` throws `malformed('region id N renders as both A and B')` when two names in `V$TIMEZONE_NAMES` map to one id. The failure is not cached, so every call re-runs the query. Flagged independently by the adversarial and edge-case lenses; code re-checked by me. Whether any real time-zone file has such aliases was not tested. Fix: keep the first or canonical name instead of throwing.
- **F2 (FIX, low): untested error-code branch in `_loadTimeZoneRegionNames`.** The verification-gap lens found that the pass-through of errors other than ORA-942/1031, and the ORA-1031 hint arm, have no unit test. The only error-path test uses 942, which both the correct and a regressed implementation handle (`test/src/connection_time_zone_region_test.dart:117-170`). The adversarial lens adds that ORA-980/1039 get no hint, and that failure is not cached so the query repeats (reviewer-reported). Fix: add 3113 and 1031 cases and decide whether to widen the hint set.
- **F3 (FIX, low): `fetchTypeHandler` contract gaps in the docs and the API.** Reviewer-reported, not reproduced.
  - Converters are synchronous and run while `_executeInProgress` is set, so the natural use (resolving a TSTZ `regionId` through the async `timeZoneRegionName`) fails with a concurrent-operation error.
  - On the eager path the handler runs after the whole result is drained, which differs from node-oracledb (the callback runs at describe time).
  - A converter that mutates its input can corrupt the carried duplicate-column source (`FetchConversion.convertBatch` `duplicateSource`, `fetch_as_string.dart`, `result_set_cursor.dart:742-748`). 
  - Fix: document all three precisely, and consider a preloaded name map exposed synchronously.
- **F4 (FIX, low, unverified): cleanup failure can replace the caller's converter exception.** Edge-case lens: in the `_executeGuarded` and `_openResultSetGuarded` catch blocks, if `forceCloseOpenResultSet`/`forceCloseOpenLobs` itself throws, the `_FetchCallbackFailure` is replaced, contradicting the "rethrown unchanged" contract. I did not read those catch blocks; verify before fixing.
- **F5 (DEFER): `fetchAsString` of a TSTZ under `preserveTimestampTimeZone: true` returns `OracleTimestampTz.toString()`,** which is `OracleTimestampTz(... regionId=N)`, a debug-style string (`oracle_timestamp_tz.dart:244-251`, re-checked). The format is now observable through `fetchAsString`, and 14.2 changed `toString` by adding `regionId`. Not comparable with node-oracledb's output. Needs a decision on a stable format.
- **F6 (DEFER): the region-id to name map is cached per physical connection,** so each pooled session pays the roughly 1,000-row `V$TIMEZONE_NAMES` query on first use (adversarial lens). It is correct but not shared.
- **F7 (DEFER, low): hidden or replaced LOB handle under `fetchLobs` in a never-delivered buffered row** (edge-case lens, `result_set_cursor.dart` `_handlesBeforeConversion`). 14.4's follow-up pass patched the related aggregate and created-temporary cases; this residual case is reviewer-reported and not tested.
- **F8 (ACCEPT): `OracleTimestampTz` `==`, `hashCode` and `compareTo` now include `regionId`,** so a decoded region value is not equal to a hand-built `+00:00` value for the same instant. This is intentional and documented (`oracle_timestamp_tz.dart:68`, CHANGELOG lines 35-36 under Unreleased, re-checked).
- **F9 (ACCEPT): binding a region-carrying value is offset-only,** and `regionId` is dropped on bind-back (story 14.2 Never list, README/CHANGELOG line 43). Region name and DST bits (byte 12 low 2 bits) are not recoverable from decode alone.
- **Dropped after re-check:**
  - "ColumnMetadata is not exported": it is, at `lib/oracledb.dart:57`.
  - "`_isLobHandleValue` excluding created-temporary LOBs is unexplained scope creep": it is 14.4's deliberate follow-up patch, with a regression test (14.4 triage log, `fetch_type_handler_test.dart` created-temporary tests per the verification-gap lens).
  - "Continuation-batch converter throw loses the original exception": the continuation `catch (_)` at `result_set_cursor.dart` rethrows, so I could not tie the claim to a source.
  - "regionId equality is a silent break": documented, see F8.
