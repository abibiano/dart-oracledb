- [x] [Review][Patch][High] `_openResultSetGuarded` never threads `fetchLobs` into `_materializeNestedCursorsInBatch`, so streaming `resultSet: true + fetchLobs: true` loses the cursor-embedded-LOB reject every other entry point enforces [lib/src/connection.dart:4112] — both call sites inside `_openResultSetGuarded` (the eager first-batch pass at :4112-4115 and the `onBatchDecoded` continuation closure at :4194-4197) call `_materializeNestedCursorsInBatch(rows, cursorColumnIndices)` with no `fetchLobs:` argument, so it silently takes the `fetchLobs = false` default. Contrast the sibling `_wrapRefCursorOutBinds`, which threads `fetchLobs: fetchLobs` with a comment explaining why, and `_wrapImplicitResultsLazy`, which omits it only because the combination is rejected pre-wire there. For a top-level SELECT projecting a nested `CURSOR(...)` column, `resultSet: true + fetchLobs: true` IS reachable (both halves are supported shapes), so `_cursorCarriesLob`/`_rejectCursorEmbeddedLob` never runs and the code proceeds into `_drainNestedCursor` — i.e. it actually attempts the fetch/decode the epic measured to be impossible (`ORA-12547` / `BufferException: Integer too large: size=114`), which on Oracle 21c additionally POISONS the transport and costs the caller the session. Every other `fetchLobs` path returns a clean pre-validated `OracleException` instead. No comment marks the omission as deliberate (unlike every other non-threading decision in this file) and no test combines `resultSet: true` with a nested `CURSOR()` LOB column. Fix: pass `fetchLobs: fetchLobs` at both sites and make `fetchLobs` a `required` parameter of `_materializeNestedCursorsInBatch` (mirroring `_openResultSetGuarded`'s own `required bool fetchLobs`) so the omission cannot recur, plus a test for the streaming shape. - [x] [Review][Patch][Med] The materialize path's Story-12.4 temp-LOB free is not exception-safe, re-opening the exact leak AC4 closed on every read-failure path [lib/src/transport/transport.dart:1950] — in `_materializeLobValues`'s `readLocator` closure, `if (locator.isTemporary) queueTempLobToFree(locator.locator);` runs only AFTER `_readClobAsString`/`_readBlobAsBytes` returns. - [x] [Review][Defer][Low] `_LobTextDecoder` misdiagnoses malformed UTF-8 as truncation, and its UTF-16 error text is unreachable [lib/src/oracle_lob.dart] — deferred, diagnostic-only and reachable only from a corrupt server stream. `_maxCarryBytes = 3` is justified as "a 4-byte UTF-8 sequence missing three continuation bytes", but the UTF-16 branch can only ever carry 0 or 1 byte, so the `isUtf16` variant of the "N trailing bytes cannot start a valid character sequence" message is dead text.
